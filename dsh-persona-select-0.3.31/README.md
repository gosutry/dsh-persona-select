# dsh-persona-select
> DSH 人设管理与选择插件：设置页管理人设与「人设历史对话」，模式选择行正下方可切换。
>
> 包内**速查页**；完整文档见 `<版本>-README-full.md`。

## 这一版你会感觉到什么
- **0.3.31：把上一版留下的那条老退路删了**（0.3.30 在「量不出几何」时还会退回 0.3.29 那套「挂在那一行里、向上展开」的就地定位 —— 那条路会把「菜单被界面挡住」重新引回来，等于留了一颗雷）。现在只有一条路：**永远是浮层**（`position: fixed` + 视口坐标，支持时再进浏览器顶层）；万一量不出位置，就用一个兜底站位（贴左边、放在窗口下三分之一），也不会被那一行管住。面板的样子、展开方向、高度上限都没变。
- **0.3.30：人设下拉的菜单改成真浮层，不再被界面挡住**（0.3.29 试过「自己算方向、自己缩高度」，可它仍然是挂在那一行里的子元素 —— 父容器一裁剪，算得再对也白算，实测被挡住的样子与改前完全一样）。现在它是 `position: fixed` 的浮层，坐标由下拉按钮当场算出来；在你的宿主支持 Popover API 时还会被抬进**浏览器的顶层（top layer）**，于是祖先的裁剪与层叠上下文一律管不着它。贴着按钮展开：上方够就向上、否则向下；高度收进可用空间（最高 320px、最低 96px，列表内部可滚），横向夹进窗口。
- **0.3.29：窗口一缩小，人设选框的菜单不再被界面挡住**（0.3.28 及更早：面板在样式里写死了「向上展开、最高 320px」，而它是挂在这一行里的绝对定位元素 —— 触发器离窗口顶部不到 320px 时（窗口被缩小、输入区被顶高），上半截面板直接画到窗口外面，表现为「菜单被挡住、上面几项点不到」；**窗口越小它不会变矮，只会越出越多**）。现在**方向与高度都是每次展开按当时的视口算**：量一下触发器上下各有多少空间，选宽的那一侧展开，并把最高高度收进那一侧 —— 窗口越小面板越矮，列表内部照旧可以滚。箭头跟着方向翻，悬停/开发核对可以看面板上的 `data-picker-place` 读数。量不出视口时退回老行为（向上、320），两侧都不够时保底 96px 而不是收成一个点不到的高度；面板收起、窗口缩放、容器滚动、行自身变高变矮都会重新量一次。外观（320 的设计上限、面板底色取主题令牌）不变。
- **0.3.27：注入的那张全页样式表不再锚通用属性名**（0.3.26 及更早：七条规则里有一条锚在裸的 `data-history-text` 上，而这张样式表是注入 `document.head`、**全页生效**的 —— 别的插件只要也用同名属性标记自己的滚动容器，它的滚动条就会被一起藏掉）。现在那条规则锚在 `data-persona-history-text` 上（属性名与样式同步改），并立下约束：凡是被这张全页样式表锚上的属性都必须带 `persona` 前缀。
- **0.3.26：主文件被别的进程换掉的那一瞬间，不再顺手删掉「对方那一份」引用的 `history/*.txt`**（0.3.25 及更早：写盘后核对发现主文件已经不是自己刚写的那一份，仍然按**自己那份**引用清单去清孤儿文件 —— 两个写者同时保存时会把对方刚写进去的人设历史正文删掉，对方再读只会看到「历史对话文件不在了」）。**读**一直是安全的；跳过这次清理最多留几个孤儿文件，下一次真正由本插件落盘的保存会清掉。
- **0.3.26：不勾「导入思考过程」时，孤立的 `</thinking>` 也一并丢掉**（0.3.25 及更早：整份文本里没出现过 `<thinking>` 就整段原样返回，于是只有一个收尾标签时它会留在导入的正文里 —— 与「孤立的收尾标签只丢它自己」的说法不一致）。
- **0.3.26：反复点开同一条人设不再把同一句话堆进常驻提醒数组**（提醒出口本来就去重，界面一直看不出差别；这条修的是那份「只在重读主文件时整体替换」的数组被逐次点选撑大的问题）。
- **分叉出来的子对话会继承父对话的设置与人设了**（0.3.24 及更早：分叉子是个新会话 id，插件只问「有没有记录 / 是不是空对话」，于是它抄的是**全局层**快照 —— 父会话选定的人设和那几个开关一眼都没看过；而采样一辈子只发生一次，那份错值再也不会被纠正）。继承在**第一次装配之前**就完成，所以子对话第一轮用的就是父那一层的人设与段序。委派的子 agent 另有一层区分：它继承设置与人设词，但**不再注入「人设历史对话」**（唯一的例外是 `subagent_fork` 从父会话日志前缀里**继承**进来的那一条 —— 那是 fork 时复制的既有事件，插件够不着它）。
- **「导入思考过程」不勾就真的一个字的思考都不留**（0.3.23 及更早：日志里带着上次导入存下、又被注入回来的那段人设历史时，`<thinking>` 会跟着注入壳**原文照发**回输入框，**取消勾选也清不掉** —— 表现为「上次的思考洗不掉、本次的洗得掉」）。压缩摘要 `<compacted-summary>` 里的思考照旧保留。
- **「导出图片」又能用了**（0.3.22 及更早：点它永远只有一句「导出失败」——那句判断写在了自己的声明之前）。
- **导出 / 导入失败一次之后，再点一次就会真的重试**（以前只能刷新页面）。
- **「当前」页那一行过滤条数改成按本对话报**（以前拿全进程累计冒充，和上面按来源的明细对不上）。
- **每轮对话只整份读一次人设文件**（以前同一轮读三遍）；**设置页与对话框共用一条状态轮询**（以前各一条）。
- **设置页 / 选择框 + 导出 / 导入都在包内分块里**：主包从约 280 KB 降到约 155 KB；分块取不到时显示的是一张可读的错误卡片（带重试），不白屏。
- **大图导出的超时从 30 秒放宽到 3 分钟**（32 MB 的 PNG 在慢网络上不再被误报超时）。
- **已知限制：同一份数据只支持单实例在写**。整份写回，两个实例同时保存时后写的会盖掉先写的，**都不报错**（实测 300 次只落一部分）。**读**安全。规避：只开一个实例；手改 `personas.json` 后先在界面上确认数字。
- **已知限制（导入会话日志）：「导入思考过程」不勾时，正文里自己写出来的 `<thinking>` 字面量会连同它后面到区段末尾的内容一起被删掉**。判据是「宁可多删，不留半截思考」（日志被截断时留着的那半截既不是正文也不是合法标记），所以一个没配对的字面量会被当成半截思考吃掉；压缩摘要 `<compacted-summary>` 包住的那一段不受影响（0.3.14 起按原文照搬）。要原样保留就把它写成 `&lt;thinking&gt;` 之类的转义写法。

## 安装
DSHA `.tar.gz`：**GUI** 设置 → 插件 → 导入插件包，或 `dsh plugin import`；装完**重启 Web**。

## 数据文件（v3，0.3.19 起）
`<DSH_HOME>/persona-select/`：`personas.json`（设置/人设）、`personas.json.v2-backup`（可删）、`history/<编号>.txt`（历史）。
